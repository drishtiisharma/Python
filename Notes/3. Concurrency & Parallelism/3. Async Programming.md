# Async Programming

## What does Sync and Async mean?

**Synchronous Programming** 
Operations execute sequentially. The program waits for the current task to fully complete before starting the next one. If a task involves waiting (such as reading a file or requesting data from a server), the entire program halts and remains idle until that specific operation finishes. Control flow is strictly **linear** and **blocking**.

**Asynchronous Programming** 
Operations can start and run without waiting for previous tasks to finish. When a task enters a waiting state, the program does not halt; instead, it suspends (the function pauses its execution at an `await` point, saves its current state) that specific task and immediately switches execution to another available task. This allows multiple operations to be in progress concurrently within a single thread of execution through cooperative multitasking. Control flow is **event-driven** and **non-blocking**.

It is highly efficient for **I/O-bound operations** (like web scraping, API calls, database queries, or file operations) where the program spends most of its time waiting for external responses. Instead of blocking the CPU during these wait times, Python hands control back to an **event loop**, which runs other tasks in the meantime.

## I/O Bound and CPU Bound Operations

**I/O-bound operations** spend most of their time waiting for external responses outside the processor, such as network requests, database queries, or file reads/writes.

**CPU-bound operations** keep the processor working at 100% capacity executing heavy calculations like machine learning, data processing, or image rendering. 

Because Python features a **Global Interpreter Lock (GIL)** that prevents multiple threads from running Python code at the exact same time, we must choose our concurrency tool based on these operation types. 

For **I/O-bound tasks**, we should use **async programming** (ideal for high-performance, single-threaded cooperative multitasking like modern web servers) or **multithreading** (which lets other threads run while one is waiting for I/O). 

For **CPU-bound tasks**, **multiprocessing** is generally preferred in CPython when we want to utilize multiple CPU cores, which completely bypasses the GIL by spawning entirely separate Python instances across multiple CPU cores to achieve true parallel processing.

| **I/O-Bound**                        | **CPU-Bound**                                                         |
| ------------------------------------ | --------------------------------------------------------------------- |
| Spends most time **waiting for I/O** | Spends most time **doing calculations**                               |
| Examples: network, files, database   | Examples: ML computation, image processing, complex calculations      |
| CPU is often **idle while waiting**  | CPU is **heavily utilized**                                           |
| **Async programming** is useful      | **Multiprocessing** is generally useful                               |
| Multithreading can also help         | Multithreading is limited in Python by the **GIL** for CPU-heavy code |

## What is GIL?

The **Global Interpreter Lock (GIL)** is a mechanism used in the standard Python interpreter (CPython) that acts as a safety lock, ensuring that **only one thread executes Python bytecode at any given time**.

**What is Bytecode in Python?**
**Bytecode in Python** is a low-level, platform-independent intermediate representation of your code that the Python interpreter generates before execution.

## Sync VS Async

| Feature               | Synchronous                                                | Asynchronous                                                                          |
| --------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| **Execution Flow**    | Strictly sequential; line-by-line.                         | Concurrent; switches between tasks during wait states.                                |
| **Blocking Behavior** | Blocks the entire program during I/O or long computations. | Non-blocking; yields control back to the event loop during I/O.                       |
| **Python Syntax**     | Standard function definitions (`def`).                     | Requires `async def` for coroutines and `await` for suspension points.                |
| **Runtime Mechanism** | Direct CPU execution.                                      | Managed by an event loop (e.g., `asyncio`) that schedules coroutines.                 |
| **Concurrency Model** | None inherent; requires threads/processes for parallelism. | Single-threaded concurrency via task switching at explicit yield points.              |
| **Code Complexity**   | Simpler to write and debug due to linear flow.             | More complex; requires managing awaitables, event loops, and avoiding blocking calls. |
| **Best Use Case**     | CPU-bound tasks or simple scripts with minimal I/O.        | High-volume I/O-bound tasks (network requests, database queries, file handling).      |

## Event Loop

An event loop is a mechanism that keeps checking async tasks and runs whichever task is ready to make progress.

In other words:

> If one task is waiting for something, the event loop doesn't sit there doing nothing. It moves to another task.



```python
import asyncio

async def task1():
    print("task 1 started")
    await asyncio.sleep(3)
    print("task 1 done")

async def task2():
    print("task 2 started")
    await asyncio.sleep(3)
    print("task 2 done")

async def main():
    await asyncio.gather(task1(),task2())

asyncio.run(main())
```

**Explanation**:
- **Start**: `asyncio.run()` launches the event loop and enters `main()`.
- **Schedule**: `gather()` queues `task1` and `task2` to run concurrently.
- **Run & Pause**: Both tasks print their "started" messages, then hit `await sleep`, yielding control back to the loop.
- **Resume 1**: After 2 seconds, the loop resumes `task2`, which prints "done" and exits.
- **Resume 2**: After 4 seconds total, the loop resumes `task1`, which prints "done" and exits.
- **End**: `main()` finishes, and the loop closes.

## `async.io` Module

**asyncio module** `asyncio` is Python’s standard library that provides the event loop, coroutines, tasks, and other primitives needed to write concurrent code using the async/await syntax. It acts as the runtime engine that schedules and manages asynchronous operations within a single thread.

#### Some Keywords

**async and await** `async def` marks a function as a coroutine that can be paused, while `await` is the specific point inside that function where execution suspends and yields control back to the event loop. Together, they form the core syntax that enables non-blocking cooperative multitasking in Python.

`asyncio.gather()` is a tool that lets us launch multiple tasks at the same time and wait for all of them to finish. Instead of waiting for one task to complete before starting the next, it runs them in parallel and gives us back all their results together once every single one is done.

## What is a Coroutine

A coroutine function is a special type of function defined with `async def` that returns a coroutine object when called, rather than executing its code immediately. Unlike standard functions, coroutines are designed to be paused and resumed; they only begin running when explicitly scheduled by an event loop and can voluntarily yield control back to that loop using the `await` keyword during waiting periods.

```python
import asyncio

async def task(name = 'task 1',delay = 3):
    print(name, 'started')
    await asyncio.sleep(delay)
    print(name, 'ended')

async def main():
    await task() # asyncio.gather() best for multiple tasks
asyncio.run(main())
```

**Note**:

> [!NOTE]
> `gather()` becomes useful when we have **multiple tasks**. It runs the coroutines **concurrently**, not "in parallel." That's an important distinction.
